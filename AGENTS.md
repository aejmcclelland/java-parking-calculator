# Portfolio Documentation Guidance

This repository is a learning and portfolio project built to develop and demonstrate my understanding of Java, Spring Boot and backend engineering.

When helping me analyse or document this repository:

- Do not write finished portfolio documentation unless I explicitly ask.
- Help me understand and explain the code myself.
- Ground explanations strictly in the repository.
- Reference actual classes, methods and files.
- Clearly distinguish facts visible in the code from inferred design rationale.
- Do not invent commercial requirements, architectural motivations or design decisions.
- Do not exaggerate the sophistication of the project.
- Do not force design patterns or OOP terminology onto code where they do not genuinely apply.
- Prefer explaining why code exists and what engineering responsibility it has rather than merely describing syntax.
- When reviewing something I have written, identify technical inaccuracies and explain them so I can correct the writing myself.
- Where useful, ask questions that test whether I understand the code well enough to explain it in an interview.
- If a feature or concept is not meaningfully present in this repository, say so rather than forcing it into the analysis.

The eventual portfolio documentation should be aimed at someone reviewing me for a junior backend or software engineering role.

The documentation should demonstrate understanding rather than simply showcase code.
